1b. HOW THE IMAGES WERE READ - METHOD AND ITS LIMITATION
------------------------------------------------------------------------------
The agent that produced this report runs on a text-only model: the harness
refuses read_image for it ('model does not declare image input'), and no
image-capable model is reachable from this session. So instead of eyeballing
the PNGs, every statement about what a chart shows was derived from the
artwork itself, which for vector charts is strictly more precise than looking
at a raster:
  * get_text('dict') gives every chart string with its font, size and exact
    position: panel titles, axis titles, tick labels, legend labels.
  * get_drawings() gives every series path; grouping them by stroke width and
    by segment-length distribution separates solid from dashed from dotted
    lines, and the path coordinates give each series' value range once the
    y axis has been calibrated from its tick-label positions.
  * the raster files were inspected by downsampling them to ASCII ink maps
    (see the cached helper sources/figures-web/_view.py) and by run-length
    measuring of the legend key marks.
The series-to-category mapping below is pinned by two independent facts:
  (1) each of Figure 1's panels carries exactly four series paths, and the
      same stroke style appears in both panels for the same category;
  (2) the value ranges are only self-consistent under one assignment - e.g.
      the category that performs ~53 bn but funds only ~14 bn must be Higher
      Education, and the one that performs ~13 bn but funds ~46 bn must be
      Federal, which is exactly how research money flows.
The dashed/dotted rendering of the individual legend keys could not be matched
to the plotted dash patterns one-to-one (the key marks and the plot marks are
drawn at different dash scales in the original artwork), so that route was
abandoned in favour of (1)+(2).

2. WHY THE PDF IS THE BEST SOURCE FOR ALL FIVE
------------------------------------------------------------------------------
The printed charts are pure vector artwork: on PDF pages 24/27/29/34
page.get_images() returns nothing and get_drawings() returns the axis,
gridline and series paths, with all chart text extractable. Vector artwork
rasterises losslessly at any resolution, so the PDF wins for every figure;
it is not a 'higher pixel resolution embedded image' but something better.
(Reality check against the brief: the PDF's charts are not embedded bitmaps
at all, so there was no fixed PDF pixel size to compare against the web PNGs.

The web edition is the weaker source on three counts:
  * graph-1-1.png (I.5) is only 624x407 px for BOTH panels of Figure 1, i.e.
    ~265 px per panel - hopelessly coarse for an ebook.
  * graph-1-2.png (I.5) is 1155x49 px and is NOT a chart: it is a thin strip
    holding the shared legend row of Figure 1 (solid key + 'Higher
    Education', dotted key + 'Business', dashed keys + 'Federal' and
    'Nonprofits'). The four key marks sit at 0 / 0.34 / 0.57 / 0.79 of the
    strip width, the same relative positions as the four legend keys of the
    printed figure (128.4 / 250.3 / 332.1 / 409.4 pt of a 128.4-483.6 pt row),
    and the first label reads 'Higher Education' glyph by glyph (its capital-H,
    i, g, h, e, r shapes were recovered from the pixels).
    => the brief's assumption 'graph-1-1 + graph-1-2 = Figure 1's two panels'
       is wrong. graph-1-1 already contains both panels; graph-1-2 is the
       legend strip.
  * the advertised 2026/08 URL for Figure 4 does not exist.
  * all the web charts are re-laid-out: graph-1-3 is 1659x1221 (1.36 aspect)
